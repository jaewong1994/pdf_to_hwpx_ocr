# pdf_to_hwpx_ocr

교재 PDF를 한글 파일(HWPX)로 바꿔 주는 **OCR30 스튜디오**의 프런트엔드입니다.
이 저장소에는 화면 한 장(`index.html`)만 들어 있습니다. 실제 판독과 조판은 내 PC에서 도는 작업 서버가 합니다.

## 구성

| 층 | 어디서 | 하는 일 |
|---|---|---|
| 화면 | GitHub Pages (이 저장소) | 로그인, 파일 업로드, 진행률, 내려받기 |
| 계정·캐시 | Supabase | 로그인, 지갑, 캐시 원장, 작업 기록 |
| 판독·조판 | 내 PC (작업 서버) | Gemini·Mathpix 호출, 한글(HWPX) 조판, 렌더 검사 |

한글 조판은 한컴오피스를 COM으로 직접 부르기 때문에 클라우드로 옮길 수 없습니다.
그래서 화면만 GitHub Pages에 두고, 작업은 집 PC가 맡습니다.

## 처음 한 번

### 0. Supabase 준비

`supabase/schema.sql` 을 Supabase 대시보드의 **SQL Editor** 에 붙여 넣고 Run 하면
지갑·원장·작업 표와 캐시 함수가 만들어집니다(문항당 100캐시로 시작).
그다음 **Authentication → Users** 에서 내 계정의 UUID 를 복사해 관리자로 지정합니다.

```sql
insert into public.ocr_admins(user_id, note) values ('여기에-내-UUID', '운영자');
```

이 저장소의 `index.html` 에는 Supabase 주소와 **publishable(공개) 키**가 들어 있습니다.
이 키는 브라우저에 노출되는 것이 정상이며, 실제 접근 제어는 RLS 와 위 함수들이 합니다.
`service_role` 키는 절대 저장소에 넣지 않습니다 — 작업 서버의 환경변수로만 씁니다.

### 1. 작업 서버 켜기 (내 PC)

```
python tools/mock_exam_ocr30/ocr30_server.py --port 8765
```

운영자 키는 환경변수로만 넣습니다. **저장소에 넣지 않습니다.**
윈도우라면 `OCR30_서버시작_예시.cmd` 를 `OCR30_서버시작.cmd` 로 복사해 키를 채우고 두 번 누르면 됩니다.

| 환경변수 | 내용 |
|---|---|
| `OCR30_SUPABASE_URL` | Supabase 프로젝트 주소 |
| `OCR30_SUPABASE_ANON_KEY` | 로그인용 공개 키 |
| `OCR30_SUPABASE_SERVICE_KEY` | 정산·해제 전용 (서버만 사용) |
| `OCR30_GEMINI_API_KEY` | 운영자 Gemini 키 |
| `MATHPIX_APP_ID` / `MATHPIX_APP_KEY` | 문항 영역 탐지, 해설 판독 |

네 개가 모두 있으면 서비스 모드(로그인·캐시)가 켜지고, 없으면 개인 키 모드로 돕니다.

### 2. 바깥에서 닿게 하기

공유기 포트를 여는 대신 터널을 씁니다.

```
cloudflared tunnel --url http://127.0.0.1:8765
```

### 3. 화면 열기

GitHub Pages 주소 뒤에 작업 서버 주소를 한 번만 붙이면 됩니다. 브라우저에 저장됩니다.

```
https://jaewong1994.github.io/pdf_to_hwpx_ocr/?api=https://<터널주소>
```

작업 서버에 직접 접속해도 같은 화면이 열립니다(`http://127.0.0.1:8765/`).
주소를 나중에 바꾸려면 화면 오른쪽 위 **작업 서버** 버튼에서 넣으면 됩니다.
서버가 꺼져 있어도 로그인과 잔액 확인은 되고, 파일 맡기기만 막힙니다.

## 화면 흐름

1. **파일 맡기기** — 문제 PDF는 필수, 해설 PDF는 선택. 해설을 주면 미주 해설까지 만듭니다.
2. **확인** — 탐지된 문항 수와 예상 캐시를 보고 시작합니다.
3. **진행** — 원형 퍼센트와 네 단계(준비 → 판독 → 조판 → 완료), 경과 시간.
4. **내려받기** — 승인 문항·소모 캐시·잔액이 정리되고 HWPX를 받습니다.

## 캐시

| 시점 | 동작 |
|---|---|
| 지급 | 관리자만 지급할 수 있습니다 (결제 연동 없음) |
| 시작 | 탐지된 문항 수 × 단가를 예약합니다. 잔액이 모자라면 시작하지 않습니다 |
| 완료 | 결과물에 들어간 문항 수만 차감하고 나머지 예약은 돌려줍니다 |
| 실패 | 예약 전액을 돌려줍니다 |

**실패한 문항은 청구되지 않습니다.**

## 계정과 캐시

관리자로 로그인하면 오른쪽 위에 **캐시 지급** 버튼이 생깁니다. 그 안에서 두 가지를 합니다.

- **계정 만들기** — 이메일과 자동 생성된 비밀번호로 지인 계정을 만들고, 개설 지급 캐시를 함께 넣습니다.
  계정 생성은 secret 키가 필요해 작업 서버가 켜져 있어야 합니다. 만들어진 비밀번호를 그대로 전달하세요.
- **캐시 지급** — 이메일로 찾아 금액을 넣습니다(음수면 회수). 이쪽은 작업 서버 없이도 됩니다.

가입 화면은 두지 않았습니다. 계정은 관리자만 만듭니다.
Supabase 대시보드의 **Authentication → Users → Add user** 로 만들어도 똑같이 동작합니다.

지갑·원장·작업 기록과 캐시 지급은 브라우저가 Supabase 를 직접 부릅니다.
그래서 작업 서버가 꺼져 있어도 잔액 확인과 지급은 됩니다.

## 보안

- 이 저장소에는 키가 들어가지 않습니다. Supabase 주소와 공개 키는 작업 서버가 `/api/health`로 알려 주고, 나머지 키는 PC 밖으로 나가지 않습니다.
- 서비스 모드에서는 세션·지갑·다운로드 모든 경로가 로그인 토큰을 요구합니다.
- 캐시 지급은 관리자만, 정산과 해제는 서버 키로만 가능합니다.

## GitHub Pages 켜기

Settings → Pages → Source를 **Deploy from a branch**, 브랜치를 `main` / `/ (root)` 로 두면 됩니다.
